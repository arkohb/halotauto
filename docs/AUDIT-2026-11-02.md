## 1. Executive summary

The trading core is in good shape: the 3EL engine is a single implementation shared by the live bot, scanner, sweep, Timeframe Scanner Bot and every backtest; its regression tests pass; the Timeframe Scanner Bot cannot place trades; the Performance Journal is per-user with 90/90 calculation tests passing; payment handling (Paystack) verifies signatures and amounts server-side and is idempotent.

The security perimeter is not. The login gate in `src/proxy.ts` only checks that a session cookie *exists*; 28 API routes rely on it alone. With a made-up cookie I read the broker list, alert settings, trade book and the TradingView webhook secret, then used that secret to submit an order to the public webhook (it reached the order checks; paper mode on the test copy). A MetaApi API token is hard-coded in source, `.env` and the SQLite database are committed to git, and MetaApi TLS certificate checking is disabled.

Architecturally, the bot, its settings, broker accounts and trade book are **one shared set per installation** (`BotConfig id="main"`). The licensing system sells per-customer licences, so in a multi-customer deployment every licensed customer would control the same bot and broker account. This needs a business decision before remediation (§15, decision D1).

Firebase and Firestore are **not used** by the application: authentication is the app's own (scrypt + database sessions) and data is in SQLite via Prisma. Firebase is only the planned host (App Hosting config written, never deployed). Checklist items that assume Firestore are marked **N/A** rather than passed.

### B. Trading strategy (3EL v1.2)

**Rules (from `engine.ts`):** candle 1 + candle 2 reverse direction (bull→bear = resistance/SELL, bear→bull = support/BUY), both bodies ≥ 0.15×ATR, C2 open within 0.10×ATR of C1 close. The dotted trigger is the C1/C2 wick extreme. Candle 3 must break beyond it by ≥ 0.02×ATR and return within 0.10×ATR — the trade fires at the line (intrabar in Instant mode). SL: fixed points (default 1000), ATR multiple, or break extreme + buffer. TP: 3R. Same-bar SL+TP = loss. Range filter skips fires when S/R < 1×ATR apart. Levels persist until fired; a broken level that never returns is removed after 24 bars. One trade at a time; all levels cleared while a trade runs. **Optional EDGE layers** (off by default except grading): break-even, partial close, trailing stop, grade gate, Capital Guardian.

## 15. Remediation checklist

**Decisions needed from you before work starts**

- **D1 — Tenancy model.** (a) *One installation per customer* (each buyer gets their own deployment, bot and broker account — matches today's design, smallest change), or (b) *shared multi-customer platform* (per-user bots, settings, brokers, trade books — a major redesign touching the engine runtime and database). Most other priorities depend on this.
- **D2 — Execution guard (T1).** Refuse to place orders when the feed is simulated or stale. This changes *when* orders are allowed, not the strategy rules. Deriv synthetics would then need a real server-side Deriv feed to trade.
- **D3 — Git history rewrite (S3).** Removing `.env`, `db/custom.db` and the token from history rewrites all commit IDs on this branch.
